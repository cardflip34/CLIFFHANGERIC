# CLIFFHANGER IC — Private Minisite

A private, password-gated, ultra-luxury minisite for the residence known as
**CLIFFHANGER IC**. Apple/Tesla-inspired minimal aesthetic, gallery-first,
production-ready.

---

## 1. Stack & Justification

**Next.js 14 (App Router) + Tailwind CSS + Vercel.**

- **Next.js middleware** is the cleanest way to gate every route server-side
  with a signed cookie — no client-side hide/show.
- **`next/image`** handles responsive variants, AVIF/WebP, and lazy loading,
  so we don't need a CDN service to look fast.
- **App Router + React Server Components** keep the public bundle small —
  important for a gallery-heavy site on cellular.
- **Vercel** deploys this stack with zero config, ships HTTPS by default,
  and DNS instructions to GoDaddy are well-trodden.
- Sharp-based local image pipeline gives us deterministic, ownerless
  derivatives — nothing depends on a third-party image host staying up.

## 4. Security

Implemented end-to-end:

- **Password gate (server-side)** in `middleware.ts`. Every route except
  `/login`, `/api/auth/*`, and static assets requires a valid HMAC-signed
  session cookie. There is no way to fetch private HTML without it.
- **HMAC-SHA256 signed cookies** in `src/lib/auth.ts` using the Web Crypto
  API (Edge-safe). Cookie is `HttpOnly`, `Secure` in prod, `SameSite=lax`,
  14-day expiry, with `exp` baked into the payload.
- **Constant-time password comparison** in `/api/auth/login` plus a 150ms
  artificial delay to flatten timing differences.
- **Rate limiting** in `src/lib/rate-limit.ts`: 5 attempts per IP per
  10 minutes on `/api/auth/login` (and `/api/inquiry`). Returns 429 with
  `Retry-After`.
- **Logout** at `POST /api/auth/logout` clears the cookie (also `GET` form
  for a quick link). Nav "Exit" button wires it up.
- **No indexing**:
  - `public/robots.txt` → `Disallow: /`
  - `<meta name="robots" content="noindex,nofollow,…">` in root layout
  - `X-Robots-Tag: noindex, nofollow, …` via `next.config.js` headers
- **Security headers** (set in `next.config.js`):
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), interest-cohort=()`
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
- `poweredByHeader: false` — drops the `X-Powered-By: Next.js` fingerprint.

## 5. Dropbox Image Ingest

Two paths — pick one.

### Path A — Dropbox API (recommended for re-runs)

1. Create an app at https://www.dropbox.com/developers/apps
2. Permissions: `files.metadata.read`, `files.content.read`. Generate an
   access token.
3. Put values in `.env.local`:
   ```
   DROPBOX_ACCESS_TOKEN=sl.xxxxxxxxxxxxxxxxxxxx
   DROPBOX_FOLDER_PATH=/Cliffhanger IC
   ```
4. Run:
   ```bash
   npm run ingest             # downloads originals into public/gallery/originals/
   npm run process-images     # creates thumb/medium/full + manifest
   ```

> Note: the shared Dropbox link in the brief is a *public link*. The Dropbox
> API requires an app token; the public link alone can't enumerate files via
> API. Use Path B if you can't generate a token.

### Path B — Manual (works with the shared link as-is)

1. Open the shared Dropbox URL in a browser.
2. Click **Download → Direct download** (downloads a ZIP).
3. Unzip and copy every image file into:
   ```
   public/gallery/originals/
   ```
4. Run:
   ```bash
   npm run process-images
   ```

Either way, the result is the same: a populated `src/content/gallery.json`
plus three derivative folders under `public/gallery/`.

### Editing the gallery

- Open `src/content/gallery.json`.
- Edit `alt`, `caption`, `section`, `order` on any entry.
- Re-running `process-images` **preserves** your edits when the `id` matches.
- To remove an image, delete its file from `originals/` and re-run.

## 8. GoDaddy DNS Mapping

### Target: `CliffhangerIC.com` and `www.CliffhangerIC.com`

In **Vercel → Project → Settings → Domains**:

1. Add `cliffhangeric.com`. Vercel flags it as needing DNS.
2. Add `www.cliffhangeric.com`. Set it as the **primary**, redirect apex →
   www (or vice versa — your call; www-primary is more conventional).

In **GoDaddy → My Products → DNS for `cliffhangeric.com`**:

| Type    | Name | Value                  | TTL |
|---------|------|------------------------|-----|
| A       | @    | `76.76.21.21`          | 600 |
| CNAME   | www  | `cname.vercel-dns.com.`| 600 |

Delete any conflicting existing `A @`, `CNAME www`, or `Parked` records that
GoDaddy added at registration. Leave MX/TXT (email, SPF) records alone.

> Vercel's apex IP is `76.76.21.21`. CNAMEs always point at
> `cname.vercel-dns.com.` (trailing dot is the FQDN form GoDaddy accepts).

|---------|------|--------------------------------|

## 9. SSL Verification

After DNS propagates (usually < 30 min, up to 24h):

1. In **Vercel → Domains**, both `cliffhangeric.com` and
   `www.cliffhangeric.com` should show ✅ **Valid Configuration** and a
   green padlock. Vercel auto-issues Let's Encrypt certificates.
2. Hit `https://www.cliffhangeric.com` in a browser — padlock shown,
   cert valid for 90 days, auto-renewing.
3. CLI check:
   ```bash
   curl -sI https://www.cliffhangeric.com | head -n 20
   openssl s_client -connect www.cliffhangeric.com:443 -servername www.cliffhangeric.com </dev/null 2>/dev/null \
     | openssl x509 -noout -issuer -subject -dates
   ```
4. Confirm HSTS header is present:
   ```bash
   curl -sI https://www.cliffhangeric.com | grep -i strict-transport
   ```

## 11. Admin Handoff

### Change the password

1. Open **Vercel → Project → Settings → Environment Variables**.
2. Update `SITE_PASSWORD` (Production). Save.
3. Click **Deployments → Redeploy** on the latest production build (or
   `vercel --prod` from the CLI).
4. (Optional) Invalidate live sessions: also rotate `SESSION_SECRET`.
   Every existing cookie immediately fails HMAC and users will re-login.

### Update photos

```bash
# Path A
npm run ingest && npm run process-images
git add public/gallery src/content/gallery.json
git commit -m "Update gallery"
git push                          # Vercel auto-deploys

# Path B (manual)
# drop new files into public/gallery/originals/, then:
npm run process-images
git add public/gallery src/content/gallery.json
git commit -m "Update gallery"
git push
```

### Edit copy

All text lives in **`src/content/site.ts`** — overview, amenities,
location, contact, footer, nav labels. Edit, commit, push.

### Redeploy

- Vercel: push to `main`, or click **Redeploy** in the dashboard, or
  `vercel --prod`.
- Rollback: in Vercel **Deployments**, find the prior good build →
  **Promote to Production**.

### Rotate credentials

| Secret | How |
|---|---|
| `SITE_PASSWORD` | Vercel env var → update → redeploy |
| `SESSION_SECRET` | `openssl rand -hex 32` → Vercel env var → redeploy (logs everyone out) |
| `DROPBOX_ACCESS_TOKEN` | Revoke in Dropbox App Console → reissue → update env |
| `RESEND_API_KEY` | Revoke in Resend dashboard → reissue → update env |

## 13. Rollback Plan

**If a deploy goes bad:**

1. Vercel → **Deployments** → pick the last known-good deploy →
   **Promote to Production**. Live in < 30s.
2. Or via CLI: `vercel rollback <deployment-url>`.

**If DNS is misconfigured (site unreachable):**

1. In GoDaddy DNS, revert the changes:
   - Remove the new `A @` record.
   - Remove the new `CNAME www` record.
   - Restore the prior parked-page or forwarding record (GoDaddy keeps a
     history under **DNS → Recent activity**).
2. TTL was set to 600s, so propagation back is fast.

**If password is compromised:**

1. Rotate `SITE_PASSWORD` and `SESSION_SECRET` (both) in Vercel env.
2. Redeploy. All current cookies are invalidated; new password required.

**If the Dropbox token leaks:**

1. Dropbox App Console → revoke. Reissue. Update env. Redeploy.
   (Tokens are only used at ingest-time on the operator's machine —
   they aren't shipped to the browser.)
